## 环境准备

### 1. 安装依赖

```bash
# 后端依赖
cd backend
pip install -r requirements.txt

# 安装测试依赖
pip install pytest pytest-cov pytest-asyncio pytest-html
```

### 2. 配置环境变量

```bash
# 创建 .env 文件
cd backend
cp .env.example .env

# 编辑 .env 文件，配置数据库和密钥
```

### 3. 初始化数据库

```bash
# 运行数据库迁移
alembic upgrade head

# 或使用 SQLite (开发环境默认)
# 数据库文件会自动创建在 backend/lifemanager.db
```

### 4. 启动后端服务

```bash
cd backend
python main.py
```

服务启动后，访问 `http://localhost:8000/health` 验证服务状态。

## 测试结果解读

### 测试状态标识

| 标识 | 含义 | 说明 |
|------|------|------|
| `PASSED` | ✅ 通过 | 测试用例执行成功 |
| `FAILED` | ❌ 失败 | 断言失败，功能有问题 |
| `ERROR` | ⚠️ 错误 | 测试执行出错，可能是代码问题 |
| `SKIPPED` | ⏭️ 跳过 | 测试被跳过，通常是有条件跳过 |
| `XFAIL` | ⚠️ 预期失败 | 已知问题，标记为预期失败 |

### 通过率评估

| 通过率 | 评估 | 建议 |
|--------|------|------|
| >95% | ✅ 优秀 | 可以发布 |
| 90-95% | ✅ 良好 | 可以发布，建议修复部分问题 |
| 80-90% | ⚠️ 可接受 | 需要评估失败的严重性 |
| <80% | ❌ 不合格 | 必须修复后再发布 |

## 常见问题处理

### 问题1: 数据库连接失败

**错误信息**:
```
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) unable to open database file
```

**解决方案**:
```bash
# 检查数据库文件是否存在
cd backend
ls -la lifemanager.db

# 如果不存在，创建数据库
alembic upgrade head

# 或删除旧数据库重建
rm lifemanager.db
alembic upgrade head
```

---

### 问题2: Fixture 未找到

**错误信息**:
```
fixture 'db' not found
```

**解决方案**:
```bash
# 确保在 backend 目录下执行测试
cd backend
python -m pytest tests/ -v

# 不要在项目根目录执行
# 错误: python -m pytest backend/tests/ -v
```

---

### 问题3: 导入模块失败

**错误信息**:
```
ModuleNotFoundError: No module named 'app'
```

**解决方案**:
```bash
# 添加 PYTHONPATH
export PYTHONPATH="${PYTHONPATH}:$(pwd)"
python -m pytest tests/ -v

# 或使用 pytest.ini 配置 (已配置)
# pytest 会自动添加路径
```

---

### 问题4: 测试数据冲突

**错误信息**:
```
AssertionError: 该用户名已注册
```

**解决方案**:
```bash
# 清理测试数据库
cd backend
rm lifemanager.db
alembic upgrade head

# 或使用隔离测试数据库
export DATABASE_URL=sqlite:///test.db
python -m pytest tests/ -v
```

---

### 问题5: 端口被占用

**错误信息**:
```
OSError: [Errno 48] Address already in use
```

**解决方案**:
```bash
# 查找占用端口的进程
lsof -i :8000

# 杀死进程
kill -9 <PID>

# 或修改端口
# 在 main.py 中修改端口配置
```

## 持续集成

### GitHub Actions 示例

创建 `.github/workflows/test.yml`:

```yaml
name: Run Tests

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v2
    
    - name: Set up Python
      uses: actions/setup-python@v2
      with:
        python-version: '3.10'
    
    - name: Install dependencies
      run: |
        cd backend
        pip install -r requirements.txt
        pip install pytest pytest-cov pytest-asyncio
    
    - name: Run tests
      run: |
        cd backend
        python -m pytest tests/ -v --cov=app --cov-report=xml
    
    - name: Upload coverage
      uses: codecov/codecov-action@v2
```

## 测试最佳实践

### 1. 编写可维护的测试

```python
# ✅ 好的实践 - 使用 fixture
@pytest.fixture
def test_user(db):
    user = User(username="test_user", email="test@example.com")
    db.add(user)
    db.commit()
    yield user
    db.delete(user)
    db.commit()

# ✅ 好的实践 - 测试独立性
def test_create_goal(db, test_user):
    goal = Goal(user_id=test_user.id, title="测试目标")
    db.add(goal)
    db.commit()
    assert goal.id is not None
```

### 2. 测试命名规范

```python
# ✅ 好的命名
def test_create_task_success(db, test_user):
    pass

def test_create_goal_invalid_title(db, test_user):
    pass

# ❌ 不好的命名
def test_task(db):
    pass
```

### 3. 使用断言库

```python
# ✅ 使用 pytest 断言
assert task.title == "学习Python"
assert task.status == "pending"
assert task.id is not None

# ✅ 使用更具体的断言
with pytest.raises(ValueError, match="标题不能为空"):
    TaskService.create_goal(db, user_id=1, title="")
```

### B. 常用 pytest 参数

| 参数 | 说明 |
|------|------|
| `-v` | 详细输出 |
| `-q` | 安静模式 |
| `-x` | 遇到失败就停止 |
| `--tb=short` | 简短的错误信息 |
| `--tb=long` | 详细的错误信息 |
| `--tb=line` | 每个错误一行 |
| `-k "keyword"` | 只执行包含关键字的测试 |
| `-m "marker"` | 只执行标记的测试 |
| `--maxfail=3` | 最多3个失败就停止 |
