## 3. 项目背景

### 3.1 Phase 1 回顾

Phase 1 已完成的核心功能：
- ✅ 用户注册登录
- ✅ 创建目标
- ✅ AI 生成规划
- ✅ 任务列表（按日期分配）
- ✅ 完成任务

### 3.2 当前痛点

通过 Phase 1 的实际使用和用户反馈，发现以下问题：

| 痛点 | 描述 | 影响 |
|------|------|------|
| **时间粒度太粗** | 任务只分配到"某一天"，没有具体时间段 | 用户不知道该在当天的什么时间完成任务 |
| **时间冲突无法检测** | 多个任务分配到同一天，但不知道是否时间冲突 | 用户可能过度安排，无法按时完成 |
| **无法进行日程管理** | 不能与其他日程（会议、约会等）进行整合 | 无法实现完整的时间管理 |
| **任务优先级不明确** | 同一天多个任务，不知道先做哪个 | 影响执行效率和完成度 |
| **时间估算不准确** | 只有预估总工时，无法分配到具体时段 | 容易超时或安排不合理 |

### 3.3 产品愿景

**愿景**：将 LifeManager 从"任务清单"升级为"智能日程助手"，让用户不仅能知道"要做什么"，还能知道"在什么时候做"。

---

## 4. 产品目标

### 4.1 核心目标

1. **时间细粒度管理**：从"天级"升级到"小时级"任务安排
2. **智能时间分配**：AI 自动为任务分配最佳时间段
3. **冲突检测与解决**：自动检测时间冲突并给出解决建议
4. **灵活调整**：支持用户手动拖拽调整任务时间段
5. **可视化展示**：提供日历视图和时间线视图

### 4.2 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 任务按时完成率 | >85% | 统计按时完成任务比例 |
| 用户满意度 | >4.5/5 | 问卷调查 |
| 平均任务分配准确度 | >80% | AI 分配时间的采纳率 |
| 时间冲突减少率 | >70% | 对比 Phase 1 和 Phase 2 的冲突次数 |

### 6.2 功能详细描述

#### 6.2.1 时间段任务创建 (P0)

**用户故事**：
```
作为用户，
我希望创建任务时可以选择具体的时间段（如 09:00-11:00），
这样我就知道确切在什么时候执行该任务。
```

**验收标准**：
- [ ] 创建任务时可选择日期、开始时间、结束时间
- [ ] 自动计算任务持续时间（结束时间 - 开始时间）
- [ ] 持续时间必须 ≥ estimated_hours（不能小于预估时间）
- [ ] 开始时间必须早于结束时间
- [ ] 跨天任务支持（如 22:00-次日02:00）
- [ ] 时间格式：HH:mm（24小时制）
- [ ] 表单验证提示友好

**界面原型描述**：
```
┌─────────────────────────────────────┐
│ 创建任务                            │
├─────────────────────────────────────┤
│ 任务标题：学习 Python                │
│ 目标：成为程序员                     │
│                                     │
│ 日期：[2026-03-03 ▼]                │
│ 开始时间：[09:00] ▼                 │
│ 结束时间：[11:00] ▼                 │
│                                     │
│ 预估工时：2 小时                     │
│ 实际时长：2 小时                     │
│                                     │
│ [取消]          [创建任务]          │
└─────────────────────────────────────┘
```

#### 6.2.2 智能时间分配 (P0)

**用户故事**：
```
作为用户，
我希望 AI 能自动为我分配任务时间段，
这样我就不用手动计算和安排时间了。
```

**验收标准**：
- [ ] 点击"智能分配"按钮，AI 自动为任务分配时间段
- [ ] 考虑用户的空闲时间（可配置）
- [ ] 考虑用户的作息习惯（可配置）
- [ ] 考虑任务优先级和截止日期
- [ ] 避免时间冲突
- [ ] 支持批量智能分配
- [ ] 显示分配结果，用户可手动调整

**分配算法规则**：
1. **优先级排序**：高优先级任务优先分配
2. **截止日期优先**：临近截止日期的任务优先
3. **连续性考虑**：同一目标的任务尽量安排在连续时间段
4. **避免疲劳**：不要长时间安排高强度任务
5. **预留缓冲**：任务之间预留 5-15 分钟缓冲时间
6. **考虑用户习惯**：
   - 早起型用户：上午安排重要任务
   - 夜猫型用户：下午/晚上安排重要任务
   - 午休时间：12:00-13:30 避免安排

#### 6.2.5 冲突检测 (P0)

**用户故事**：
```
作为用户，
我希望系统自动检测任务时间冲突，
这样我就不会安排重复的时间段了。
```

**验收标准**：
- [ ] 创建任务时自动检测时间冲突
- [ ] 显示冲突的任务列表
- [ ] 提供冲突解决建议（调整时间、删除冲突任务等）
- [ ] 智能分配时自动避免冲突
- [ ] 拖拽调整时实时检测冲突
- [ ] 冲突提示醒目清晰

**冲突类型**：
1. **完全重叠**：时间段完全相同
2. **部分重叠**：时间段有交集
3. **包含关系**：一个时间段包含另一个

**解决建议**：
- 自动调整到最近的空闲时间段
- 调整任务优先级，推迟低优先级任务
- 将任务分割到多个时间段

## 8. 用户体验设计

### 8.1 交互流程

#### 8.1.1 创建任务流程

```
开始
  ↓
填写任务基本信息（标题、描述、预估工时）
  ↓
选择日期
  ↓
[选择 A] 手动选择时间段
  ├─ 选择开始时间
  ├─ 选择结束时间
  └─ 验证时间有效性
      ↓
[选择 B] 智能分配时间
  ├─ AI 计算最佳时间段
  ├─ 显示分配结果
  └─ 用户确认或调整
      ↓
查看冲突检测结果
  ↓
[如有冲突] 解决冲突
  ↓
创建任务
  ↓
结束
```

#### 8.1.2 智能分配流程

```
开始
  ↓
收集任务列表
  ↓
分析用户习惯（作息、偏好）
  ↓
获取固定日程
  ↓
按优先级排序任务
  ↓
为每个任务分配时间段
  ├─ 避开固定日程
  ├─ 避开已安排任务
  └─ 考虑任务连续性
      ↓
检测冲突
  ↓
[如有冲突] 调整分配
  ↓
显示分配结果
  ↓
用户确认
  ↓
结束
```

## 9. 数据模型设计

### 9.1 核心数据模型

#### 9.1.1 Task（任务）模型扩展

**新增字段**：

| 字段名 | 类型 | 说明 | 必填 |
|--------|------|------|------|
| start_time | Time | 开始时间 | 是 |
| end_time | Time | 结束时间 | 是 |
| actual_start_time | DateTime | 实际开始时间 | 否 |
| actual_end_time | DateTime | 实际结束时间 | 否 |
| reminder_enabled | Boolean | 是否开启提醒 | 默认 true |
| reminder_minutes_before | Integer | 提前提醒分钟数 | 默认 30 |

**修改字段**：

| 字段名 | 旧类型 | 新类型 | 原因 |
|--------|--------|--------|------|
| estimated_hours | Integer | Float | 支持小数小时（如 1.5h） |

#### 10.1.1 AI 智能时间分配算法

**输入参数**：
- 任务列表（包含预估工时、优先级、截止日期）
- 用户时间偏好（作息、工作时段）
- 固定日程列表
- 已安排任务列表

**输出结果**：
- 每个任务的建议时间段

**算法流程**：
1. 预处理：
   - 按优先级和截止日期排序任务
   - 计算可用时间段（排除固定日程和已安排任务）
2. 分配任务：
   - 为每个任务找到最佳时间段
   - 考虑任务的连续性（同一目标的任务连续安排）
   - 在任务之间预留缓冲时间
3. 冲突检测：
   - 检测任务之间是否有时间冲突
   - 如有冲突，调整低优先级任务
4. 返回分配结果

#### 10.1.2 冲突检测算法

**输入**：
- 新任务的时间段（开始时间、结束时间）
- 已存在任务的时间段列表

**输出**：
- 冲突任务列表

**算法**：
```python
def detect_conflict(new_start, new_end, existing_tasks):
    conflicts = []
    for task in existing_tasks:
        # 检测是否有时间交集
        if not (new_end <= task.start_time or new_start >= task.end_time):
            conflicts.append(task)
    return conflicts
```

#### 10.2.3 时间线视图实现

**核心逻辑**：
1. 将 00:00-24:00 按 15 分钟刻度分割
2. 计算每个任务在时间线上的位置和高度
3. 渲染任务块
4. 支持拖拽交互

**示例代码**：
```vue
<template>
  <view class="timeline">
    <view
      v-for="hour in 24"
      :key="hour"
      class="timeline-hour"
    >
      <text class="hour-label">{{ formatHour(hour) }}</text>
      <view class="hour-line"></view>
    </view>
    <view
      v-for="task in tasks"
      :key="task.id"
      class="task-block"
      :style="getTaskStyle(task)"
      @touchstart="handleDragStart(task)"
      @touchmove="handleDragMove"
      @touchend="handleDragEnd"
    >
      <text class="task-title">{{ task.title }}</text>
      <text class="task-time">{{ formatTime(task.start_time) }}-{{ formatTime(task.end_time) }}</text>
    </view>
  </view>
</template>

<script>
export default {
  props: {
    tasks: Array
  },
  methods: {
    getTaskStyle(task) {
      const startMinutes = this.timeToMinutes(task.start_time)
      const endMinutes = this.timeToMinutes(task.end_time)
      const totalMinutes = 24 * 60

      return {
        top: `${(startMinutes / totalMinutes) * 100}%`,
        height: `${((endMinutes - startMinutes) / totalMinutes) * 100}%`
      }
    },
    timeToMinutes(timeStr) {
      const [h, m] = timeStr.split(':').map(Number)
      return h * 60 + m
    },
    formatHour(hour) {
      return `${hour.toString().padStart(2, '0')}:00`
    }
  }
}
</script>
```
