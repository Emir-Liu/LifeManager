## 2. 需求概述

### 2.1 背景

当前 AI 对话功能存在以下问题:
1. 用户发送消息后,界面不会立即显示用户发送的消息
2. AI 回复采用一次性返回完整内容,用户体验不够流畅
3. 用户在等待 AI 回复时,无法感知 AI 是否正在处理
4. AI 回复中的格式化内容(如标题、列表、代码)无法正确显示

### 2.2 目标

1. **即时显示用户消息**:用户发送消息后,立即在界面上显示用户消息
2. **流式输出 AI 回复**:AI 回复采用流式输出,逐步显示内容
3. **提升用户体验**:让用户能够实时看到对话进展
4. **Markdown 格式解析**:AI 回复内容支持 Markdown 格式,正确显示标题、列表、代码等格式化内容

## 3. 功能需求

### 3.1 即时显示用户消息

**需求描述**:用户点击发送按钮后,立即在消息列表中显示用户发送的消息

**功能点**:
1. 用户输入消息后点击发送
2. 前端立即将用户消息添加到消息列表
3. 用户消息显示发送状态(如"发送中...")
4. 同时向后端发送消息
5. 后端返回成功后,更新消息状态

**界面效果**:
```
用户: 你好
[消息立即显示]
[可能显示发送中状态]
```

---

### 3.2 流式输出 AI 回复

**需求描述**:AI 回复采用流式输出,逐步显示内容,提升用户体验

**功能点**:
1. 后端支持流式响应(Server-Sent Events 或 Streaming)
2. 前端逐步接收并显示 AI 回复
3. AI 回复开始时显示"正在输入..."提示
4. 流式接收过程中实时更新消息内容
5. 流式接收完成后,隐藏"正在输入..."提示

**界面效果**:
```
AI: [正在输入...]
AI: 你好!
AI: 你好! 我很高兴能帮助你...
AI: 你好! 我很高兴能帮助你。有什么我可以协助你的吗?
```

---

### 3.3 消息持久化

**需求描述**:所有用户消息和 AI 回复必须保存到数据库,页面刷新后能够恢复对话历史

**功能点**:
1. **用户消息保存**:用户发送消息后,立即保存到数据库
2. **AI 回复保存**:AI 回复完成后,保存完整的回复内容到数据库
3. **页面刷新恢复**:页面刷新时,从数据库加载对话历史消息
4. **状态同步**:前端临时消息状态与数据库记录同步

**技术实现**:
- 后端在流式输出接口中保存用户消息和 AI 回复
- 后端 `get_conversation_messages` 按 `sequence` 降序返回消息(最新的在前)
- 前端页面加载时调用 `/conversations/{id}/messages` 接口获取历史消息
- 前端接收消息后需要反转顺序，将最早的消息排在前面
- 前端收到 `user_message` 和 `ai_complete` 事件后更新临时消息为数据库消息

**数据流程**:
```
1. 用户发送消息
2. 前端立即显示临时消息(标记 pending)
3. 后端保存用户消息到数据库
4. 后端返回 user_message 事件(包含数据库记录)
5. 前端更新临时消息为数据库消息
6. AI 流式输出回复
7. 后端保存 AI 回复到数据库
8. 后端返回 ai_complete 事件(包含数据库记录)
9. 前端更新 AI 消息为数据库消息
```

## 4. 技术实现方案

### 4.1 后端实现

#### 4.1.1 流式输出接口

**新增接口**: `POST /conversations/{conversation_id}/chat/stream`

**响应格式**: Server-Sent Events (SSE)

**示例代码**:
```python
from fastapi.responses import StreamingResponse
from app.services.chat_service import chat_service

@router.post("/{conversation_id}/chat/stream")
async def chat_stream(
    conversation_id: int,
    data: ChatRequest,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db)
):
    """流式 AI 对话"""

    # 1. 保存用户消息
    user_message_data = MessageCreate(
        role="user",
        message_type="text",
        content=data.message
    )
    user_message = service.add_message(conversation_id, current_user.id, user_message_data)

    # 2. 获取对话历史
    messages = service.get_conversation_messages(conversation_id, current_user.id, 0, 10)
    history = [
        {"role": msg.role, "content": msg.content}
        for msg in messages[:-1]
    ]

    # 3. 生成流式响应
    async def generate_stream():
        # 先返回用户消息
        yield f"event: user_message\ndata: {json.dumps(message_to_dict(user_message))}\n\n"

        # 流式输出 AI 回复
        ai_response = ""
        for chunk in chat_service.chat_stream(data.message, history):
            ai_response += chunk
            yield f"event: ai_chunk\ndata: {json.dumps({'content': chunk})}\n\n"

        # 保存 AI 回复
        ai_message_data = MessageCreate(
            role="assistant",
            message_type="text",
            content=ai_response
        )
        ai_message = service.add_message(conversation_id, current_user.id, ai_message_data)

        # 返回完整消息
        yield f"event: ai_complete\ndata: {json.dumps(message_to_dict(ai_message))}\n\n"

    return StreamingResponse(
        generate_stream(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"
        }
    )
```

#### 4.1.2 ChatService 流式方法

**新增方法**: `chat_stream`

```python
from typing import AsyncIterator

async def chat_stream(
    self,
    user_message: str,
    conversation_history: List[Dict] = None
) -> AsyncIterator[str]:
    """流式发送消息并获取回复

    Args:
        user_message: 用户消息
        conversation_history: 对话历史记录(可选)

    Yields:
        AI 回复的每个 chunk
    """
    # 构建消息列表
    messages = []
    messages.append({"role": "system", "content": self._get_system_prompt()})

    # 添加历史对话
    if conversation_history:
        for msg in conversation_history[-6:]:
            if msg.get('role') in ['user', 'assistant']:
                messages.append({
                    "role": msg['role'],
                    "content": msg.get('content', '')
                })

    # 添加当前用户消息
    messages.append({"role": "user", "content": user_message})

    # 调用 LLM 流式接口
    llm = self.llm_operator.get_llm()
    stream = llm.stream(messages)

    # 流式输出
    for chunk in stream:
        content = chunk.content if hasattr(chunk, 'content') else str(chunk)
        yield content
```

```javascript
// 流式 AI 对话
const chatWithAIStream = async (conversationId, content) => {
  if (!conversationId || isSending.value) {
    throw new Error('对话ID无效或正在发送中')
  }

  isSending.value = true
  isTyping.value = true

  // 创建临时 AI 消息用于流式显示
  const tempAiMessage = {
    id: `temp-${Date.now()}`,
    conversation_id: conversationId,
    role: 'assistant',
    message_type: 'text',
    content: '',
    created_at: new Date().toISOString(),
    streaming: true
  }
  messages.value.push(tempAiMessage)

  try {
    await conversationApi.chatWithAIStream(conversationId, {
      content: content
    }, (event, data) => {
      // 处理流式响应
      if (event === 'ai_chunk') {
        // 追加内容
        tempAiMessage.content += data.content
      } else if (event === 'ai_complete') {
        // 替换为完整消息
        const index = messages.value.findIndex(m => m.id === tempAiMessage.id)
        if (index !== -1) {
          messages.value[index] = data
        }
      } else if (event === 'user_message') {
        // 同步用户消息
        const index = messages.value.findIndex(m => m.pending)
        if (index !== -1) {
          messages.value[index] = data
        }
      }
    })

    return tempAiMessage
  } catch (error) {
    console.error('AI对话失败:', error)
    // 移除临时消息
    messages.value = messages.value.filter(m => m.id !== tempAiMessage.id)
    throw error
  } finally {
    isSending.value = false
    isTyping.value = false
  }
}
```

#### 4.2.3 修改 conversation.js API

**新增方法**: `chatWithAIStream`

```javascript
// 流式 AI 对话
chatWithAIStream(conversationId, data, onEvent) {
  return new Promise((resolve, reject) => {
    const requestTask = uni.request({
      url: `${this.baseURL}/conversations/${conversationId}/chat/stream`,
      method: 'POST',
      header: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${getToken()}`
      },
      data: {
        message: data.content
      },
      responseType: 'text',
      success: (res) => {
        if (res.statusCode === 200) {
          // 解析 SSE 响应
          const lines = res.data.split('\n')
          let currentEvent = null

          for (const line of lines) {
            if (line.startsWith('event:')) {
              currentEvent = line.substring(6).trim()
            } else if (line.startsWith('data:')) {
              const dataStr = line.substring(5).trim()
              if (dataStr && currentEvent && onEvent) {
                try {
                  const dataObj = JSON.parse(dataStr)
                  onEvent(currentEvent, dataObj)
                } catch (e) {
                  console.error('解析 SSE 数据失败:', e)
                }
              }
            }
          }

          resolve()
        } else {
          reject(new Error(`请求失败: ${res.statusCode}`))
        }
      },
      fail: (err) => {
        reject(err)
      }
    })

    // 存储 requestTask 以便取消
    this.currentStreamRequest = requestTask
  })
}
```

## 8. Markdown 格式解析

### 8.1 功能需求

**需求描述**:AI 回复内容需要支持 Markdown 格式解析,正确显示格式化内容

**支持格式**:
1. **标题**: `# 一级标题`, `## 二级标题`, `### 三级标题`
2. **列表**: 无序列表 `* 项目`, 有序列表 `1. 项目`
3. **代码块**: 三个反引号包裹的代码块
4. **行内代码**: 单个反引号包裹的代码
5. **粗体**: `**粗体文本**`
6. **斜体**: `*斜体文本*`
7. **链接**: `[文本](URL)`
8. **换行**: 双换行符
9. **引用**: `> 引用文本`

### 8.2 技术实现

### 8.3 流式 Markdown 解析

**挑战**:流式输出时,Malformed 的 Markdown 可能导致解析错误

**解决方案**:
1. **延迟解析**:等待一个完整的段落或块级元素后再解析
2. **部分解析**:使用宽松的 Markdown 解析器
3. **渐进式解析**:先显示原始文本,流式完成后再解析 Markdown

**推荐方案**:渐进式解析

```javascript
// 在 conversation.vue 中
const useMarkdown = ref(false)

// 流式输出时显示纯文本
<view v-if="streamingMessage && !useMarkdown" class="streaming-text">
  {{ streamingMessage.content }}
</view>

// 流式完成后显示 Markdown
<MarkdownRenderer
  v-if="streamingMessage && useMarkdown"
  :content="streamingMessage.content"
/>

// 在流式输出完成后
watch(() => streamingMessage.value?.streaming, (isStreaming) => {
  if (!isStreaming) {
    useMarkdown.value = true
  }
})
```

## 9. 对话数据管理

### 9.1 数据库设计

**已实现的数据表结构**:

1. **conversations 表** - 对话会话
   - `id`: 主键
   - `user_id`: 关联用户 ID (外键)
   - `title`: 对话标题
   - `conversation_type`: 对话类型
   - `status`: 状态
   - `message_count`: 消息数量
   - `created_at`: 创建时间
   - `updated_at`: 更新时间

2. **conversation_messages 表** - 对话消息
   - `id`: 主键
   - `conversation_id`: 关联对话 ID (外键)
   - `sequence`: 消息序号
   - `role`: 角色 (user/assistant)
   - `message_type`: 消息类型
   - `content`: 消息内容
   - `model_used`: 使用的 AI 模型
   - `tokens_used`: 消耗的 token 数
   - `created_at`: 创建时间

3. **conversation_actions 表** - 对话操作记录
   - `id`: 主键
   - `conversation_id`: 关联对话 ID (外键)
   - `message_id`: 关联消息 ID (外键)
   - `action_type`: 操作类型
   - `status`: 状态
   - `description`: 操作描述
   - `created_at`: 创建时间

**数据关系**:
- 一个用户可以拥有多个对话 (1:N)
- 一个对话可以包含多条消息 (1:N)
- 一条消息可以关联多个操作 (1:N)
